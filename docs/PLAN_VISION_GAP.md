# 愿景差距补齐规划（2026-10-26 起）

> 目标依据：[路演讲稿](reference/Bianliang_Pitch_Script_20261025.pdf)。用户于 2026-10-26 决定把讲稿描述的能力逐项做到。
> 本表是 Claude（规划、验收）与 Codex（执行）的共同任务表；状态由 Claude 验收后更新。

## 工作方式

1. **Claude 规划**：每项任务写一份任务说明（目标、范围、不做什么、验收标准）。
2. **Codex 执行**：在独立 git worktree 的 `codex/<任务号>` 分支上开发，只改任务范围内的文件，不提交、不推送；完成后写"改了什么、怎么验证、还剩什么"。
3. **Claude 验收**：审代码、跑全部测试、用真实模型实测；不通过就附意见退回 Codex；通过后由 Claude 提交并合并进 `main`。
4. **主线保护**：`main` 始终保持演示可用。10-31 路演定稿前，只合并低风险且实测通过的任务；其余在分支上继续，路演后再合并。
5. 互不相关的任务可以在各自的 worktree 里并行；同一模块的任务按顺序做。

## 验收方式（2026-10-26 起）

每项任务除 Codex 自测外，Claude 另备一套 Codex 看不到的多种说法（含反例），用真实模型跑、按功能报通过率；只让例句通过的关键词补丁不算完成。
