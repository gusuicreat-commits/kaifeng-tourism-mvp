## 4.1 检查 Key 类型

必须区分：

**Web 服务 Key：**

用于 FastAPI 调用高德地点搜索和路径规划。

**Web端（JS API）Key：**

用于 Vue 浏览器地图。

JS API 通常还需要与该 Key 配套的安全密钥。

如果本机只有 Web 服务 Key，不要把它用于 JS API Loader。

如果找不到有效的 JS API Key 或安全密钥：

- 先完成离线组件、测试和配置准备。
- 明确告诉用户还需要配置什么。
- 不伪造真实地图加载成功。

此前有高德密钥出现在聊天截图中。请优先提醒用户轮换已暴露凭据，并使用新凭据完成后续配置。

不输出、记录或提交真实密钥。

## 4.2 安全密钥配置

优先使用高德官方推荐的安全代理方式。

可评估使用现有开发代理、FastAPI 服务或已有反向代理机制实现 JS API 所要求的 `serviceHost`。

要求：

- JS API 安全密钥只保存在服务端。
- 前端不写死 `securityJsCode`。
- 后端 Web Service Key 不暴露到前端。
- 代理只接受高德官方要求的合法路径及必要方法。
- 固定合法上游地址，防止成为任意网址代理。
- 不允许用户传入任意外部 URL。
- 不在日志中泄露密钥。
- 不要求为了实现代理而新建复杂基础设施。

JS API 的浏览器 Key 可以按照官方方式配置为前端可读取的公开标识，但必须使用控制台允许的安全限制；不能把它与服务端安全密钥混为一谈。

若当前环境无法安全完成 JS API 代理，先实现可验证的配置结构，并将浏览器真实加载标为 BLOCKED，不能偷偷退回明文安全密钥作为正式交付方案。

# 六、阶段三：定位功能

这是本次最重要的用户交互之一。

## 6.1 用户主动定位

保留原来的「我在这里」入口，但将其连接到真实定位功能。

建议点击后：

1. 检查浏览器和设备是否支持定位。
2. 向游客请求定位授权。
3. 调用高德 JS API 2.0 的 `AMap.Geolocation`。
4. 获取定位结果和可用精度信息。
5. 在地图上显示当前位置。
6. 根据位置调整地图视野。
7. 提供明确的成功或失败反馈。

默认不启用长期连续定位。

首次进入地图页面时，不应在没有明确交互或说明的情况下主动开始持续追踪。

## 6.2 定位结果必须有来源和时效

前端位置状态至少表达：

- 经度。
- 纬度。
- 坐标系。
- 来源。
- 获取时间。
- 可用定位精度。
- 当前是否有效。

来源可区分：

- 高德 JS API 浏览器定位。
- 浏览器原生定位。
- 游客手动地图选点。
- 游客主动选择的已知地点。

字段命名应兼容现有后端数据契约。

没有可靠精度值时不要编造。

不能将 IP 粗定位解释为 GPS 精确定位。

## 6.3 坐标系处理

高德地图使用 GCJ-02。

如果采用 `AMap.Geolocation`，应按实际返回数据及官方契约确认其坐标系。

如果使用浏览器原生 Geolocation 获取 WGS84 坐标，需要先按高德官方方法转换，再用于高德地图和相关服务。

不得将 WGS84 经纬度直接当作 GCJ-02 使用。

如果转换失败，应明确提示，不得静默使用可能偏移的坐标。

## 6.4 定位失败与手动选点

以下情况必须能够安全处理：

- 用户拒绝定位权限。
- 设备不支持。
- 浏览器不支持。
- 定位超时。
- 室内环境导致定位不准确。
- 仅能获得粗略位置。
- 页面不是 HTTPS 安全上下文。

注意：

本地 `localhost` 可以用于相应的浏览器开发测试，但手机通过普通局域网 HTTP 地址访问时，可能无法获取定位权限。

手机真实测试应准备 HTTPS 环境。

定位失败后，允许游客：

- 搜索已知地点作为出发位置。
- 点击地图选择一个点。
- 使用已保存且仍有效的手动位置。

手动选点需要用户确认后才作为本次位置来源使用。

不能假称手动位置经过 GPS 验证。

## 6.5 与旅行记忆的关系

地图上临时定位成功，不等于必须立刻修改服务端行程。

默认只更新当前界面位置状态。

如果用户明确选择：

“将这里设为本次旅行当前位置。”

再通过现有授权接口保存相应位置及来源。

保存时沿用 M7 权限、会话时效和数据删除规则。

不得建立新的隐蔽位置追踪数据库。

# 九、阶段六：路线预览与高德导航

## 9.1 路线预览

用户在地图选择某个地点后，可查看路线预览。

首版优先完成步行路线，再验证驾车与公交。

高德 JS API 2.0 官方支持：

- `AMap.Walking`
- `AMap.Driving`
- `AMap.Transfer`

请按实际插件契约接入。

路线预览至少展示：

- 起点。
- 终点。
- 交通方式。
- 返回的距离。
- 返回的预计耗时。
- 路线查询状态。

如果使用 JS API 自带路线图层进行展示，必须明确这些属于地图查询结果，而不是已通过完整旅游规划引擎校验的正式行程。

不要用两点之间的直线冒充真实道路路线。

## 9.2 路线与正式规划分离

路线预览属于地图交互。

OR-Tools 仍负责完整行程的活动顺序、时间窗、硬约束和返程等优化。

不能因为 JS API 在地图上画出一条路线，就将其直接写入正式城市规划的已核验交通数据。

已有正式 Provider 的准入限制继续保留。

## 9.3 跳转高德导航

使用官方 URI API：

https://lbs.amap.com/api/uri-api/guide/travel/route

允许游客点击：

“在高德查看路线”。

对于具有经过核验入口的景区，可以显示：

“导航到景区入口”。

如果只有景区 POI，不要将按钮文案写成“导航到准确入口”。

URI 参数必须正确编码。

移动端调起 App 不保证所有浏览器和设备都能成功，应允许使用官方 Web 路线页面作为备选。

不要自己开发实时语音转弯导航。
