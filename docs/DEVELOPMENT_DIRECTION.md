## 2026-10-20方向修订时的问题与取舍

本节保留当时的判断依据，“当前 planner”“尚未实现”等描述是旧单景区快照；城市引擎、素材篮和助手的后续实现以现状页及下节为准。

1. **范围扩展与旧期限不匹配。** 城市级规划需要入口、交通、餐饮和跨场景状态，不能仅改首页文案。采用有限地点、单日、先一种交通方式的 V1；保留城市闭环，重新估排期。具体首个现场样区按数据完成度选择，不替用户假定已经选定。
2. **两份文档的阶段编号容易误读。** 地图文档先基础导览、再城市闭环；总览将城市闭环定义为 V1。统一为 V1 内两个工程里程碑；只有基础导览不能宣布正式 V1 完成。
3. **“动态重规划”不能等到 V2 才从零做。** V1 已要求手动途中改行程，必需当前状态、起点和进度；V2 增强自然语言及可信自动变更。现有 M7 复用，但当前完成进度后仍拒绝重规划，应显式补齐。
4. **“AI 智能体”不意味着开放式自主执行。** 原文没有要求多 Agent 或特定框架。V1 继续固定工作流和确定性工具，后续只在验证收益后放宽编排，授权和路线提交始终由服务端掌管。
5. **防错过演出依赖的不止开始时刻。** 还要结束时间、场地位置、路程、停止入场、缓冲与数据时效。当前 planner 有候场而没有独立入场缓冲；这两个概念不能互换。承诺改为“按当前依据预计可衔接”，并保留不确定性。
6. **两场演出可能在同一场地。** 当前求解器每个 POI 最多一次，无法自然表达同场地多场。新模型分开地点和活动实例，纳入测试，不把原地等待误算为冲突或重复地点错误。
7. **“想吃小吃”不等于可以导航到一道菜。** 菜品偏好需匹配真实餐饮地点；营业、停留和转场必须进入时间预算。未核验商户只能保留候选。
8. **地图跳转不等于城市联合规划。** 外部地图链接没有自动提供后端估时；需路径服务适配或限定范围的核验步行数据。园内出入口与园外地点也要明确对应。
9. **统一行程不等于强行跨图连线。** 园内示意坐标、OSM WGS84 与地图服务坐标要经适配；入口未知、图不连通或再入园规则未知时不能补直线和默认通行。
10. **保留旧路线不能掩盖已知失效。** 重算失败保留版本，但已取消的演出或过期路段必须标记失效；不能继续展示为可执行推荐。
11. **“少操作”与确认不是每步弹窗。** 直接、类型明确的按钮可表达用户意图；自然语言和重要目标取舍必须确认。所有提交仍需服务端复核，不通过省略后端校验换取一键体验。
12. **减少绕行不等于牺牲体验。** 对照任务必须保留相同必选目标。增加自愿体验导致路线更长时，不能判产品失败；也不能删目标后宣称路程改善。研究创新性需要独立查新，本轮不作此结论。

## 当前实现差距与下一步

2026-10-23核对：状态、引擎、素材篮、助手、地图及参考问路已有软件实现；剩余工作应按真实资料和验收缺口组织，不能继续把全部城市能力排为从零开发。

| 工作 | 已有基础 | 剩余门槛 |
| --- | --- | --- |
| 数据样区 | 事实契约、受控导入、采集代码与候选包 | 核验入口/道路、目标日完整场次、营业/再入园、餐饮供应和返程；导入形成有限真实链 |
| 城市状态 | 草稿、进度、锚点、候选确认、路线版本及删除门禁 | 在真实资料下验收；旧单景区显式转换、账号与跨设备恢复未完成 |
| 时间与路线 | 联合 CP-SAT、独立校验、方向交通与费用包入口 | 正式交通时段依据、入口转换与现场误差校准 |
| 途中修改 | 当前锚点、已完成前缀、锁定项保护与剩余规划工具 | 一次真实中途调整与有效接续走查 |
| 地图与助手 | 正式状态投影、素材篮、条件工作区、有限 Agent、参考问路 | 知识问答修复、输出复核、真机定位/跨 App 返回、复杂任务延迟和容量 |
| 验收与维护 | 分轮软件回执、版本/授权/故障测试 | 已知浏览器失败收口，V01–V18逐项证据、现场和游客比较；能力接口旧描述仍需修正；团队交接已建立Git基线，远端协作另行确定 |

优先完成有限真实链，再做现场和用户任务。首个走查样区、目标日、人员及新的交付日期仍需按实际条件确定。高德参考服务已真实调用，不再列“尚无 Key”，但其成功不能替代正式交通准入。

| 编号 | 场景 | 应有结果 |

| V07 | 场次无结束、过期、取消或场地不明 | 待确认或冲突，不认证完整观看与衔接 |

| V09 | 设备定位拒绝、位置过期或示意坐标 | 支持手动已知地点；不伪造定位或路段 |
| V10 | 点菜品但无商户、商户关门 | 保留兴趣或提示替代，不安排虚构餐饮 |
| V11 | 转场接口失败、路网断开、入口未映射 | 保留草案与缺口，无直线或零时间替代 |
| V12 | 出园后再入园规则未知或不允许 | 不自动设计该路线；明确受影响目标 |
| V13 | 无 LLM、无客流、无地图 Key | 点选与已有确定性能力可用；缺失部分如实降级 |
| V14 | 确认前场次更新、候选过期、并发提交 | 拒绝旧候选或版本；重试不重复写入 |
| V15 | 求解失败、事务失败、真实取消后重算失败 | 不覆盖旧版本；取消部分仍标失效 |
| V16 | 导航跳转返回、刷新和地图模式切换 | 同一城市行程和版本、进度连续 |
| V17 | 非本人 ID、会话到期、删除与旧备份恢复 | 城市及所有子对象同样被授权和删除约束保护 |

## 游客体验实验口径

对照为官方导览 + 普通地图 + 美食平台，实验组为汴梁游记。使用同一任务、必选体验、可获得事实和日期；尽可能采用交叉顺序并平衡使用顺序，记录熟悉度与学习效应。无法在同一现场条件比较时，分别报告桌面任务与现场结果。

| 指标 | 记录口径 |
| --- | --- |
| 规划耗时 | 从阅读相同任务到确认满足要求的方案；失败单列，不只统计成功者 |
| 按时到场比例 | 在事先定义的截止前实际到达的有效目标场次数 / 需参与评估的有效目标场次数；取消、主动放弃与失约分列，分母为零记不适用 |
| 无效绕行 | 相同必选体验与通行条件下的实际重复/多余行走；明确参考路线，主动新增体验不算无效 |
| 调整耗时 | 从收到同一变更任务到确认新的有效剩余安排；求解延迟另行记录 |
| 跨场景完成率 | 完成预定义景区、餐饮、城市接续任务的人次 / 尝试人次；失败和数据缺口保留 |
| 操作难度 | 完成任务的步骤、误操作、求助与中断，不只比较聊天轮数 |
| 满意度 | 预先固定量表、问题和采集时点，报告样本量、分布与未回应 |

先做小规模试用找问题，再据效应和波动确定正式样本量与分析方法；本版不编造提升百分比。工程测试数据、人工模拟任务与现场实测分开保存。少走路和求解目标下降不能替代“更省心”的体验证据。

## 本轮文档校验
