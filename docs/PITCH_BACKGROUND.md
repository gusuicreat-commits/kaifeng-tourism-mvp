## A. 对外口径

### A1 一句话定位
**汴梁游记是一个开封城市旅游 AI 助手“小汴梁”：它主动了解游客的偏好，把景点、演出、美食放进同一张时间表，排出可执行的一日或多日行程，并在出发后随时按游客的一句话重新调整。**

### A2 四个核心优势

**1. 双模式自适应交互：问得出，也做得到**
- **深度互动 / 快速安排两种模式，随时切换**：
  - 深度互动：小汴梁主动提问，用点选方式了解游客的节奏、交通方式和最在意的事（少走路、少花钱、少等待），再生成行程；
  - 快速安排：减少询问，没说的信息按默认值补齐（明天、9:00—20:00、从开封府出发并返回），直接生成方案，并明确告诉游客用了哪些默认值，想改一句话就行；
  - 规划表单和对话框上都有模式切换，两边同步；说“直接帮我排个行程吧”“你看着安排吧”也能直接出方案。
- 完整规划流程：首页自由浏览 → 收藏进素材篮（可跳过，可一键使用推荐的开封夜游路线）→ 开始规划 → 填写日期、时间、出发与返回地点、人数 → 选择互动模式 → AI 了解需求 → 生成候选方案 → 确认保存。
- 小汴梁会主动提问：
  - 游客刚开始规划时，弹出点选式偏好卡片，问“这次旅行你不想遇到什么”（走太多路、行程太赶、花太多钱）和“想怎么在景点之间移动”（走路、公交地铁、打车），点一下就行，不用打字；
  - 缺什么信息就追问什么，比如哪天去、几点出发、从哪出发，已经说过的不再重复问。
- 回答直接变成排程条件，方案出来后逐项说明：哪些已经按你的要求调整，哪些没能采用、为什么。
- 差异点：很多 AI 旅行助手也会追问，但问完往往只是生成一段文字。小汴梁问到的每个偏好都落实到行程计算里，并且给出可以核对的结果。

**2. 兴趣素材篮驱动的规划：AI 帮你取舍**
- 游客把感兴趣的景点、演出、美食放进素材篮，小汴梁结合时间、距离、营业时间和演出场次做取舍和组合。
- 排不下时，AI 会说明“这版不再安排”的内容，游客可以确认或改为候补。
- 说法建议：“把收藏变成行程”。不要说素材篮是首创，Dream Trip、SwipeCity 等产品有类似的收藏功能，我们的差异在于收藏之后由 AI 直接排进可执行的时间表。

**3. 本地化多类型信息融合**
- 本地资料库覆盖开封：
  - 467 个地点：37 个景区、52 家餐厅、184 个演出舞台、25 个景区入口；
  - 787 个演出节目、1536 场演出场次；
  - 32 家特色商家的口味、人均、招牌菜，以及 450 条营业规则。
- 景区、演出、餐饮放在同一张时间表里统一规划，导航直接跳转高德地图，可以导到离你最近的景区入口。
- 问路时可显示高德估算的打车费、过路费，以及景区附近的停车场。

**4. 一体化生成、出行准备与途中调整**
- 一句话生成一日或多日行程，比如“明天到11月2日在开封玩三天，每天早上九点从开封府出发，晚上八点回开封府”。
- 多日行程可以只改某一天，比如“第三天改成十点出发”，其他天保持不动。
- 出发以后，今天剩下的和后面几天可以一起改，比如“今天和明天都少走路”“后面两天都坐出租车吧”“今天以后都别开车了，坐公交”。
- 所有改动都先出预览，确认后才保存，并保留历史版本，可以恢复。
- 支持加景点、删景点、少走路、放慢节奏、改交通方式、按人数核对预算；住宿费计入全程预算，还没有价格的项目会单独列出“未计入”。
- **出行准备清单**：问“我要带什么”“出门需要带哪些东西”，小汴梁按你已确认的行程算出清单，每条都写明依据，例如“穿双舒服的鞋：这趟行程步行约 3.1 公里”“带件外套：行程会持续到晚上 20:30”“提前到场：行程里有 2 场演出，最早一场 19:00 开始”。
  - 同时接入和风天气每日预报，按行程日期补充提醒，并写明日期和数值，例如“带把伞：11月1日预报降水概率最高 45%”“注意保暖：11月2日最低约 8°C”；行程日期太远、还没有预报时，会提示临近出发再问。
  - 清单由系统按行程和预报计算，不靠模型编写，所以不会出现与行程对不上的建议。

### A3 技术亮点（申报书技术部分可用）
- **大模型理解 + 确定性核对**：
  - 大模型负责理解游客的话；
  - 系统逐项核对模型提取的内容和游客原话是否一致，对不上的不采用并如实告知，避免 AI 自作主张；
  - 事实、计算和行程提交由确定性服务完成。
- **约束求解排程**：用 OR-Tools 统一处理营业时间、演出场次、转场时间、步行距离、预算和节奏。
- **预览—确认—版本**：任何改动先预览，确认后提交，版本可回溯。
- **工程质量**：
  - 3374 项后端自动化测试，7 组共 155 项浏览器端到端测试；
  - 其中“完整规划流程”一组直连真实后端：从首页浏览一路点到确认行程，覆盖深度互动、快速安排、跳过素材篮和中途切换模式；
  - GitHub 持续集成全部检查通过；
  - 用 105 条真实模型能力评测持续回归（多数轮次 104/105 通过，最低 102/105）。

### A4 和竞品的对比（建议写法）
| 维度 | 通用 OTA / AI 助手 | 小汴梁 |
|---|---|---|
| 提问 | 会追问，结果多为文字建议 | 点选式偏好卡片，回答直接变成排程条件，并逐项说明落实情况 |
| 交互节奏 | 固定流程 | 深度互动 / 快速安排两种模式，随时切换 |
| 景点 + 演出 + 美食 | 分散在不同页面 | 同一张时间表统一排程 |
| 出发后调整 | 多需重新生成 | 一句话调整今天剩余和后面几天，先预览再确认 |
| 可信度 | 可能编造细节 | 只采用和原话核对一致的内容，做不到的如实说明 |
| 出行准备 | 通用清单，可能包含与行程无关或无法核实的细节 | 按游客自己的行程和目标日天气预报计算，每条附依据 |

注意：**不要写“携程、飞猪不能主动提问”**。它们的 AI 助手会追问，评委可能当场反驳。我们的差异是“问了以后真的落实到行程里，并且可以核对”。

### A5 演示建议（这些说法都经过真实模型验证）
1. 完整流程（深度互动）：首页打开“开封府”详情 → 加入素材篮 → 素材篮点“交给小汴梁安排” → 日期点“明天”、时间 09:00—20:00、出发和返回都选“开封府府门广场入园衔接点” → 点“2 人” → 选“深度互动” → 点“轻松”“步行”“少走路” → 继续 → 生成安排 → 确认。
2. 完整流程（快速安排）：首页点“规划我的开封之旅” → “用推荐的开封夜游路线” → 同样填日期、时间、地点、人数 → 选“快速安排”，直接出 3 份候选（开封府、第一楼、鼓楼夜市三处都排进）→ 确认。也可以在对话框切到“快速安排”后说“给我出个方案吧”。
3. 对话里的偏好卡片：新行程不走表单、直接进对话时，在卡片上点“走太多路”“行程太赶”“公交地铁”，再输入“明天早上九点从开封府出发，晚上八点回开封府”。
4. 问城市推荐：“开封有什么好玩的”或“推荐几个景点”。
5. 多日行程：“明天到11月2日在开封玩三天，每天早上九点从开封府出发，晚上八点回开封府”，确认后说“再加一个包公祠”“第三天改成十点出发”。
6. 出发后调整（需要当天的行程已经开始）：“今天和明天都少走路”“后面两天都坐出租车吧”。
7. 行程确认后问“我要带什么”，展示按行程和天气预报算出的准备清单（日期选在未来 7 天内，才有预报）。

### A6 下一阶段（写成迭代方向）
- 取舍原因说明：排不下的景点逐个说明原因，比如距离太远或与演出时间冲突。
- 酒店条件筛选：房型、窗户、早餐等条件匹配。
- 天气联动调整：根据天气预报调整多日行程。
- 个性化推荐：根据游客历史收藏，持续推荐相似内容。
