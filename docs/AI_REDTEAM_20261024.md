# 小汴梁 AI 红队测试与修复验收

日期：2026-10-24。按“先复现 → 确定根因 → 方案 → 修改 → 回测”执行；本报告是服务端防线与软件流程验收，不是实际模型攻击成功率评估。

## 结论与范围

修复后的完整后端 **679 passed**，其中 **54 项**为本轮专用红队用例；最终 Chrome 浏览器闭环 **7 passed**。Agent 与城市助手输入契约检查通过。原后端基线为625项；两组计数重叠，不相加。

首轮19个定向反例中17个失败，2个正向控制通过；之后沿失败路径扩展到54项，最终全部通过。后续补充发现了位置临界过期、交通方式误映射、跨轮硬限制丢失等问题。阶段回执与前后结果见 [机器报告](reports/ai-redteam-20261024.json)。

所有测试使用临时数据库和合成资料，模型输出由受控替身注入；**本轮真实 Kimi 请求0次、真实高德请求0次**。没有读取真实游客对话作为攻击语料，没有修改正式数据库、M7删除台账或留存规则，也没有构建或替换前端。前端 src/dist 的逐文件指纹核对未变；既有采集工程的并行改动保留。

本轮没有新增 Agent 框架、微服务、依赖或数据库迁移，没有放宽工具白名单、引擎复核和显式确认要求。未执行8017重启或独立发布；代码是否被现有开发进程自动重载不作为本轮验收证据。

## 修复后的设计

`原文 + 本次正式上下文 → 有界规则/结构化模型输出 → 引文与修改证据/枚举语义校验 → 原受控工具 → 原路线复核 → 用户确认 → 原版本/事实/事务门`。

### 意图输入

- 原文子串是必要条件，不能单独构成修改授权。
- 证据门采用有限中文模式，对含糊的否定、举例、条件句保守澄清；它不是完整中文语义解析器，可能要求用户改用更明确表达。
- “最好”和“必须”继续分开；不得因容量限制仅处理前半段，也不得从模型的合法枚举反推用户表达过该偏好。
- 没有新增“取消全部规则”“自动确认”等工具。模型输出未知字段、私有所有者、SQL、未注册工具、假引文、错误数值和互斥形态均不能升级为执行权限。
- 负向食物条件只做安全识别/澄清；没有真实食材及供应数据，不提供过敏原安全保证。

### 任务与临时记忆

- task_id独立于request_id；前者是服务端临时任务身份，后者仍是每会话幂等键。历史回执无需回填。导出按回执result.task_id关联任务，而非假设两种ID相等。
- 容量检查与进程内任务预留在同一锁内；数据库写失败时释放预留。并发重复回执不再依赖“先提交回执、后登记任务”的间隙。
- 关闭留存时，当前step仍返回本次答复，供前端展示；同一终态任务之后的GET/重试返回`history_not_retained`占位，不能恢复先前原文。正式路线与已授权业务状态仍走原接口读取。
- 处理中为完成本次请求必需的临时上下文仍存在；本轮不声称Python进程或供应商网络请求中的字符串可被物理擦除。既有purge同时清理完整请求文本，避免在途取消对象保留另一份原文。
- 原15分钟临时任务范围、每会话3份运行任务和全局128份进程内限制保持；不等于跨进程租约或多游客容量验收。

### 输出与事实

`conversation`本轮没有提交/监测依据时，常见完成和实时物理断言会被替换；`result.response_guard`说明此次回复是确定性拦截结果。模型原断言不会继续作为公开understanding中的正常答复保留。

这个检查是有限模式门，**不能证明任意自然语言都真实**。事实、场次、营业、交通、客流和提交状态依旧应走确定性工具；稳定知识解释与业务事实区分的完整改造仍见旧[知识问答诊断](AGENT_KNOWLEDGE_QA_DIAGNOSIS.md)，本轮没有把那份诊断包装成已完成知识问答升级。

## 测试覆盖与失败修正过程

1. 原有后端625项通过后，才添加攻击预期与失败回执。首轮19项中17失败、2通过。
2. 第一批修复后19项全通过，邻近旧功能154项通过。
3. 继续加入枚举错配、临界过期、终态取消/超时隐私、日历问题、跨轮硬约束、并发和外部名称注入，扩至42项通过。
4. 对回复门添加反向控制时发现本轮补丁把“已保存的行程可以查看”误拦截，已修复并保留RT23；不能把该问题算作原系统既有漏洞。
5. 全量曾有一项失败：参考问路需要位置时丢失旧state/code。修复保持`needs_position / current_position_required / CURRENT_ORIGIN_REQUIRED`，不要求明确命名起点提供GPS；保留对应旧测试及RT24。
6. 最终专用54项、完整后端679项通过，最终浏览器7项通过。测试结果有重叠，不相加。

保持通过的关键旧边界：跨属主/CSRF、版本冲突、候选过期、事实取消、已完成前缀、锁定目标、未知商家/交通、取消在途预览、工具白名单/前置条件、重复行动和预算、历史关闭/导出/删除，以及模型401/429/超时/非法输出。

浏览器使用真实HTTP、现有frontend/dist、Chrome 375px视口、独立8021临时服务与合成库/Mock模型；验证实际候选生成、显式确认、放弃、缺供应、冲突协商、刷新和日期变化使旧候选失效。未测试线上容量或真实游客任务。

## 剩余边界

- 没有新增真实Kimi攻击、语言质量或独立游客语料评测；Mock输出证明服务端能拦截该载荷，不证明真实模型会/不会生成它，也不提供攻击成功率。
- 复杂否定、引用嵌套、未知表达和开放式答复仍可能出现理解偏差；当前采取保守澄清。回复模式检查不是通用事实证明或完整提示注入防御。
- 稳定知识问答、菜品解释与实时商家事实的体验问题未在本轮全面重构；依旧需要单独的证据分层与真实模型评测。
- 单进程任务/限流仍不具备跨进程恢复和分布式配额保证；没有增加后台主动执行或自动重试。
- 真实客流、道路、场次、供应、入口、现场位置与手机导航不在本轮软件反例中被“补齐”或认证。没有训练或声称验证任何机器学习准确率。
