# 行程规划算法与验证边界

核对日期：2026-10-23。城市引擎是当前开发主线；旧单景区求解器继续兼容。产品要求见 [PRD](PRD.md)，详细输入、限制与命令见 [PLANNING_ENGINE_V1](PLANNING_ENGINE_V1.md)。

## 当前实现

| 能力 | 实际代码与边界 |
| --- | --- |
| 城市首次与剩余规划 | `city/engine/solver.py`、`tools.py`、`prepare.py`；同一 CP-SAT，不为重规划复制算法 |
| 活动候选 | `context.py`；地点、节目日期场次、真实餐饮供应分别消解；同地不同场次是独立活动 |
| 时间及预算 | `models.py`、`solver.py`；整数秒、同业务日、营业窗口、完整时长、最晚到场、返程、明确硬预算与步行限制 |
| 方向交通与出入口 | `travel.py`；按起终点、模式及有效期选有依据的时段包络；缺边不补零、不补直线 |
| 园内图 | `network.py`；仅使用显式核验的有向路网，不拿旧示意图当真实通行证据 |
| 地图适配 | `engine/amap.py` 提供报价适配；`city/agent/reference_routes.py` 提供参考问路。真实报价成功不等于正式矩阵已准入 |
| 独立复核 | `validation.py`；复查候选、路径、时间、营业、入口、锁定目标、前缀和预算，确认及正式读取再次检查 |
| 版本与失败保护 | `service.py`；预览不提交，确认检查授权、CAS、事实指纹和时效；失败不覆盖正式版本，已失效历史标 stale |
| 旧单景区 | `paths.py`、`itinerary.py`、`planner.py`；一个 scenic_id、每地点最多一次等是旧接口限制，不能泛化到城市引擎 |

## 目标和时间判断

先满足有效事实和硬约束，再比较可选目标、交通、步行、费用、等待与修改幅度。必去和锁定体验不能为缩短路线被静默删除。权重和默认停留是工程参数，不是训练结果或游客收益证据。

```text
最晚到场 = min(有依据的停止入场时刻, 开演 - 提前到场缓冲)
保守到达 = 上一活动结束 + 转场耗时上界 + 未包含的进出园转换
时间余量 = 最晚到场 - 保守到达
```

默认缓冲不是排队实测；计划等待不是现场排队。无结束时刻不能按零计算，无营业或再次入园规则不能默认可行。超时与模型证明不可行分别返回，FEASIBLE/OPTIMAL 均只相对于当前输入模型。

剩余规划保留实际完成/跳过前缀和锁定目标，从有效当前锚点及当前时间接续。恢复历史版本也需生成新候选，经当前事实检查后确认，不能直接回滚版本或删除台账。

## 正式交通的缺口

正式引擎读取服务端运营包；非合成资料须有来源、路径与坐标依据、覆盖规划区间的可靠时段估计、进出园转换及需要的成本。高德当前时点的参考结果不能直接充当全天保守上界。真实入口、园内通行、交通校准及完整场次仍需核验。

旧客流服务在有效非模拟观测不足时降级普通规划，不推断畅通，不声称精确排队或实时避堵。

## 验证与研究

软件案例、合成算法基准、真实地图调用、现场走查和游客效果分别记录。[项目现状](PROJECT_STATUS.md)汇总现有验收边界；[历史算法报告](archive/stages-20261020-23/ALGORITHM_TEST_REPORT.md)仅证明当时单景区范围。

验收按 [DEVELOPMENT_DIRECTION](DEVELOPMENT_DIRECTION.md) 的 V01–V18。研究在相同事实、必选体验和预算下比较基线，先报告失败与违约，再比较距离、耗时和修改幅度；没有独立查新或实验，不声称方法新颖或效果提升。依赖许可见 [THIRD_PARTY](THIRD_PARTY.md)。
