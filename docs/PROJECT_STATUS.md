## 按优先级处理的缺口

1. **真实业务闭环**：核验有限地点的入口、通行、目标日完整场次、营业与再入园规则、真实商家及供应，再经受控入口导入；正式交通还需可靠时段依据和入口转换。
2. **助手可靠性**：10月24日已完成一轮服务端红队修复，证据见[本轮报告](AI_REDTEAM_20261024.md)；知识问答与实时业务事实仍存在过宽限制；[诊断报告](AGENT_KNOWLEDGE_QA_DIAGNOSIS.md)不能作为修复完成证明。还需协议错误、工具实际执行和答复语义的复验。
3. **输出复核**：参考草案要检查总步行、预算、时间及缺项，不能在关键事实待确认时声称满足全部条件。[10月24日草案](reports/plan-20261024-draft.md)存在摘要与正文步行量不一致，本轮未改写历史产物。
4. **延迟与容量**：模型调度仅同进程共享；既有 3 RPM 保守配置下的复杂任务成功曾用约126秒，不能证明45秒产品预算及多游客容量可用。
5. **验收收口**：处理已知浏览器失败，补真机 HTTPS 定位、外部导航返回、真实跨场景路线及途中修改走查；游客对照实验另行验证效果。
6. **能力接口与版本管理**：Agent capabilities 已补充 Provider Registry 的逻辑能力和当前状态；旅行服务查询已通过 `city/providers/` 注册表接入现有 FlyAI/高德适配器，并保留 `provider_trace`。天气适配器仍未绑定通用查询 workflow；`city/api.py` 的历史 `city_assistant_frontend` 说明仍需后续专项清理。团队交接已整理首次Git源码基线、按提交导出的源码包与离线bundle；具体提交号见交付包HANDOFF_VERSION.json。本轮没有创建或推送远端。
