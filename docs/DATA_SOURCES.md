版本 v2.1，2026-10-21。依据 [PRD.md](PRD.md)、既有两份产品文档和本轮[城市旅游数据清单](reference/bianliang_data_guide_20261021.pdf)。数据需求、关联、建议量级和四类任务验收统一见[DATA_REQUIREMENTS.md](DATA_REQUIREMENTS.md)；本文记录来源与接入边界。优先打通地点/入口/访问规则、节目场次、菜品—商家供应证据、城市转场及行程状态；客流作为后续增强。本轮没有重新联网核验或导入运行库。

## 证据状态

采集到资料不等于事实已经核验；事实核验不等于已完成实体映射和系统接入；系统可计算不等于现场路径已走通。分别记录采集、核验、映射、导入及走查状态。

每条正式使用的事实至少包含稳定 ID、来源 ID、发布者、来源定位、采集时间、适用日期或区间、核验时间与方法、冲突状态和版本。位置增加坐标系；道路增加范围和可通行证据；估计另有方法与不确定性。

“已核实”仍需限定日期、范围和字段。非模拟标志只是数据属性，不能自动证明真实、最新或适合导航。

OSM 道路与官方导览图均为候选证据。面中心、图上标签和未声明坐标系的地图中心不能作为精确入口。旧工程探针失败的记录与本次采集包已取得候选道路并不矛盾，不能继续据旧探针声称“没有道路数据”。

当前应用的 seed 仍定义两套本地示意路网和 504 条模拟客流；是否另有运行时导入需单独查询运行库，本次未做数据库审计。采集包脚本不会自动修改应用数据库。首页展示图是主题图，不称实景；当前餐饮图片本身不证明商户或位置。

## V1 最小数据包 待建立

以下是一条真实跨场景链路的接入条件，不要求首版补齐全城：

1. 一处重点景区的限定核验范围：入口、出口、节目场地及必要连接路段；节点和边有稳定 ID，连通、通行与坐标均通过核对。
2. 至少一场用于真实演示的目标日期演出，含开始、结束或可靠持续时间、场地、适用日和状态。两场衔接及同场地多场需额外构造工程案例并按实际数据做现场验证。
3. 一处餐饮地点：真实名称、明确位置、营业依据、核对时间、菜品关联及用餐时长的参数来源。未知排队独立标记，不能混入测量结果。
4. 一处城市游览或夜游地点及返程终点，核对必要的营业、开放与访问限制。
5. 园内外每次交接的入口对应、进出园耗时、票种及再入园规则。未知再入园规则不默认开放。
6. 每段城市转场有适用交通模式和时间依据。允许核验过的有限步行走查数据作为明确标注的替代，不允许只有导航链接就通过全程时间验收。

## 各类来源与使用规则

美食事实分菜品、商家、供应关系三层。菜单、商家公开资料或实地证据必须能够支持具体供应边；地点搜索通常只能提供商家候选，不能当完整菜单。价格和用餐缓冲可用有方法来源的范围，不能伪装成已测排队。园内外归属、营业和二次入园决定能否把用餐插进演出间隙。

城市路线优先在规划或重规划时请求高德，保存必要的请求及结果元数据，缓存服从来源条款。高德是本轮明确的优先接入方向，不表示当前已获得Key、接口权限或真实估时响应。无需自建全市路网或预采集所有地点对；现有provider边界及限定人工走查降级仍有效。

官方日期公告、经营者确认和现场核验优先用于节目及营业事实。地图服务用于位置与道路估时；OSM 可作路网候选，缺 access 或 foot 标签不能推断允许通行。不同来源冲突时保留原值和证据，按适用日期、字段与核验结果解决，不静默挑更方便的时间。

节目介绍不等于具体场次；开演不等于结束；检票时段不等于完整营业时间；门外演出不一定受园内开放时段约束；宣传“多次入园”不等于所有票种均适用。需要逐项建立实体、时间和规则关系。

城市路线服务必须记录供应商、起终点、坐标系、模式、出发时间、获取时刻、有效期、估时及可用几何。地图组件能画路线不代表已经取得合法可用的估时接口。凭证、配额及使用条件在选择服务时核实，本轮不凭文档指定已经开通的供应商能力。

对公开网页、图片和地图，公开可读不等于可以任意转载。继续保留采集包来源与复用说明；本轮只把用户提供的两份 PDF 原样保存为内部方向依据。

## 导入与发布流程

先保留原始证据，再归一化实体和坐标，核对字段与有效期，解决冲突，验证道路和时间，最后通过维护工具导入。数据入口输出拒绝项及原因，不能静默填默认值。正式路线引用事实版本，更新或取消应触发受影响方案重新检查。

演示数据与真实候选分开。模拟只用于明确标记的工程演示和测试；游客正式规划不混入。数据缺口可以保留在待确认草案中，不能生成全程已核验的状态。

现有单景区日程导入工具为 `scripts/import_schedules.py`。记录字段为 id、scenic_id、node_id、kind、name、starts_at、ends_at、valid_date、source_id、source_url、publisher、collected_at、verified、is_simulated；kind 为 show/opening，全景区开放的 node_id 可为 null。日期与时间带时区，当前跨午夜区间需拆分。

2026-10-21 已实现独立 `city-facts/1` 事实入口，覆盖地点、来源、入口、营业规则、节目、日期场次、菜品、商家与供应关系；维护 CLI 为 `scripts/import_city_facts.py`。默认在内存副本校验，显式选择数据库并 `--apply` 才原子写入；无游客写入口。关联和版本冲突整批拒绝，过期、取消、演示、权限未知及依赖缺失返回不可用。字段、模板与命令见 [CITY_STORAGE_AND_FACTS.md](CITY_STORAGE_AND_FACTS.md)。运行库已建空表，未导入真实或合成城市事实；这不表示真实高德、道路导入或全程规划已接通。上述旧数据现状表仍按原采集日期解释。

当前采集包没有应用内部 node_id 的完整映射；缺 ends_at 的节目不能直接设为 verified 有效场次。真实 GeoJSON 也不能直接替换本地示意坐标。

## 客流保留能力与边界

既有 `Observation` 导入仍使用 `scripts/import_crowds.py` 或维护 API。必填 scenic_id、node_id、observed_at、source_type、source_name、measurement_kind、confidence、is_simulated；count 和 crowd_level 至少一个，人数无容量不推断拥挤等级。汇总须有 period_end，时间须带时区；不能接受未来观测。

当前观测使用时效和可信度筛选；历史参考按点位与时段、日内聚合再跨日等权，至少三个有效日期。它不是已训练模型，也不随每一站到达时刻滚动预测。代码实际规则以 crowds.py 和 crowd_provider.py 为准。

保留官方匿名汇总、实地观测、经授权第三方的来源记录。节假日总接待量不能转换为某个舞台某时刻人数，天气不能当客流标签。游客反馈需记录时间、地点、样本数、去重与有效期，不自动等同官方观测。

无可靠数据不提供“人少”判断，不把历史热度当实时拥挤。只有取得匹配的现场数据并独立验证后，才考虑拥挤等级、排队估计或路段避堵增强。

## 数据验收

逐条检查来源可追踪、关键字段完整、坐标适配、日期有效、路网连接、真实入口、商户定位及冲突处理。现场走查单独记录实走路线、实际用时和与估计的差异。通过 CSV 或 GeoJSON 结构检查不代表景区开放、道路可走或演出能赶上。

本轮修订的验收与待办见 [DEVELOPMENT_DIRECTION.md](DEVELOPMENT_DIRECTION.md)，原数据说明存于 `.backups/direction-20261020/docs/DATA_SOURCES.md`。

外部“数据整理.zip”的路由脚本仅适合候选分析：同起终点在verified模式仍输出约28米虚拟绕行，正式接入前须修正；清洗不等于新增或核实数据。
